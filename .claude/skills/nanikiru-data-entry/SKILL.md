# 何切る問題のデータ登録

自然言語で提供された何切る問題を、`data/problems/NNNN.json` に登録する。

## 絶対に守ること

**牌の枚数・シャンテン数・受入枚数を自分で数えない。** 必ず `functions` の `npm run check` を実行して、ソルバーの計算結果を使う。LLMの計算ミスが学習データに混入すると、学習データそのものが汚染される（design doc §6.3）。

**不明点は推測しない。** 局・自風・巡目・ドラのいずれかが提供された文章から読み取れない場合は、ユーザーに質問する。

## 手順

### 1. 局面を抽出する

提供された文章から以下を読み取る。

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 局 | ✓ | `東1局`〜`南4局` |
| 自風 | ✓ | `東家` / `南家` / `西家` / `北家` |
| 巡目 | ✓ | 1〜18 の整数 |
| ドラ | ✓ | **ドラそのもの**。ドラ表示牌で書かれていたら1つ進めた牌に直す |
| 手牌 | ✓ | **ツモ牌を含まない純手牌** |
| ツモ牌 | — | 副露直後のみ省略 |
| 副露 | — | `{"type": "pon", "tiles": [...]}` 形式 |
| 正解の打牌 | ✓ | |
| 正解の理由 | ✓ | 原典の解説をそのまま使わず、要点を自分の言葉でまとめる |

牌の表記は `1m` / `1p` / `1s` / `東南西北白発中` / `赤5m` に正規化する。
`123m` のような略記は1枚ずつに展開する。

### 2. 枚数を確認する

`手牌 + 副露×3 + (ツモ牌があれば1) = 14` を満たすか確認する。

| 副露数 | 手牌（ツモあり） | 手牌（副露直後） |
| --- | --- | --- |
| 0 | 13 | — |
| 1 | 10 | 11 |
| 2 | 7 | 8 |
| 3 | 4 | 5 |
| 4 | 1 | 2 |

合わない場合は書き出さず、ユーザーに差し戻して確認する。

### 3. 下書きを作る

`data/problems/` の既存ファイルを見て**次の連番**を決める（4桁ゼロ埋め）。
`rejected` は空、`meta.reviewed` は `false` で下書きする。

```json
{
  "id": "0001",
  "situation": {
    "round": "東1局",
    "seat": "南家",
    "turn": 7,
    "dora": ["5s"],
    "hand": ["1m","2m","3m","4m","5m","6m","7m","8m","9m","東","東","1p","2p"],
    "draw": "5s",
    "melds": []
  },
  "answer": {"discard": "5s", "reason": "..."},
  "rejected": [],
  "meta": {"split": "train", "source": "...", "createdAt": "YYYY-MM-DD", "reviewed": false}
}
```

`meta.split` は既定で `train`。ユーザーの指示があればそれに従う。

### 4. ソルバーで検証する

```bash
cd functions && npm run check --silent -- ../data/problems/NNNN.json
```

出力を確認する。

- **エラーが出たら書き出しをやり直す。** 牌が重複しすぎている、枚数が合わない、正解の打牌が手牌にない、などが検出される
- 「正解はソルバー上の最良手ではありません」と出た場合、正解の理由が**打点・場況・安全度**に触れているかを確認する。牌効率だけを根拠にしているなら、理由が不十分なのでユーザーに確認する
- 正解のシャンテン数・受入枚数を理由文の裏付けとして使う

### 5. 悪手を決める

`npm run check` が提案する悪手候補をユーザーに提示し、採用するものを選んでもらう。

提案は種別つきで出る。

| 種別 | 意味 |
| --- | --- |
| シャンテン戻し | 正解よりシャンテン数が大きくなる |
| 受入大幅減 | 同じシャンテン数で受入が正解の60%未満 |
| 打点放棄 | 赤ドラ・ドラを切り、受入も増えない |
| 字牌の誤処理 | 正解が字牌残しのときにその字牌を切る |

採用した悪手それぞれに理由文を書く。

**理由文は「その打牌を選んでしまう典型的な誤った思考過程」を書く。** 「なぜ悪いか」の説明ではない。dispreferred 側の【理由】として使われるため、その打牌を正当化する（誤った）論理でなければならない。

| 種別 | 理由文の方向性 |
| --- | --- |
| シャンテン戻し | 特定の手役・好形への固執を根拠に、シャンテン戻しを正当化する |
| 受入大幅減 | 目先の1つの受けだけを見て、全体の受け入れ幅を無視する |
| 打点放棄 | 速度のみを重視し、赤・ドラの打点価値を軽視する |
| 字牌の誤処理 | 「字牌は早く処理する」という原則を機械的に適用する |

不自然になるものは**無理に採用しない**。件数を減らしてよい。

### 6. 確定する

`rejected` を書き込み、`meta.reviewed` を `true` にして、もう一度 `npm run check` を通す。
最後にユーザーへ、登録した問題の要約（ID・局面・正解・採用した悪手）を報告する。
